# RX Debugging and Performance Plan

## Goal
Identify why adaptive RX still freezes after a few lines and determine the actual bottleneck on Galaxy S / Galaxy 5.

## Proposed Debug Meters
Add lightweight counters updated in `ReceiveActivity` and shown in the status/mode text:
1. Capture rate (`RATE`).
2. Measured decode load (`mLoadAvg`).
3. Audio frames received per second.
4. Decoder `process()` calls per second.
5. Scope lines produced per second.
6. Received image lines per second.
7. UI posts per second.
8. Last UI update interval (`now - mLastUiMs`).
9. Last scope update interval (`now - mLastScopeMs`).
10. Current mode name and image dimensions.
11. Number of automatic rate fallbacks.
12. Time since last fallback.

## Implementation Notes
- Use `SystemClock.uptimeMillis()` counters reset every second.
- Keep all counters in `ReceiveActivity`; do not allocate in the hot path.
- Update the displayed text only inside the existing `postUi()` path.
- Log fallback events with old/new rate and measured load.

## Next Diagnostic Step
After collecting meter readings from Galaxy S and Galaxy 5, compare:
- Whether freezes correlate with a load spike, UI starvation, or decoder line stalls.
- Whether rate fallback actually occurs and at which rate the device stabilizes.
- Whether scope/image line production stops while audio continues.
